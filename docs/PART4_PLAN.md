# Part 4：响度匹配与自然听感

制定日期：2026-11-12。基线提交：`90dc5c3`。阶段状态：`TODO`，本文件是执行计划，功能尚未开始实现。

本计划将 Part 4 对齐 [路线图 Phase 4](ROADMAP.md#6-phase-4响度匹配与自然听感)，主任务为 DG-040、DG-041、DG-042。补齐它们需要的 DG-023 响度显示及 DG-032 预设接口，原任务编号继续保留。

## 1. 阶段目标

让不同本地音频切换时，持续过响的内容逐渐接近同一目标响度，同时保留耳语、呼吸、雨声等素材本来的细节。将“声音更平稳”和“是否自然”分别用信号测量、素材 A/B 和真机听感验证。

默认只衰减过响内容，自动增益上限为 0 dB；较轻的内容可以继续低于目标。界面显示正在观察、正在调整、保持轻声或直通的实际状态。

## 2. 当前基础与范围

已有压缩器、LUFS 分析器、保守 4× 峰值保护和本地 PCM16 播放桥。上一阶段通过 142 项 JVM 测试、九组原生测试、120 组独立峰值对照，并保存 300 项性能矩阵，详见 [阶段证据](evidence/dg014-015-2026-11-12/README.md)。

本阶段处理 DreamGuard 自己播放的单/双声道 PCM16，采样率仍为 8–192 kHz。其他布局和失败回退沿用现有策略。系统媒体音量、睡眠定时和第三方播放器共存行为维持原有职责。

第三方播放器的音频捕获与替换继续归 DG-050；本计划不会依据本地处理结果扩大其能力范围。播放列表、网络播放、Windows、进度条和离线整文件预扫描另行安排。完整后台/锁屏/蓝牙验收仍由 DG-030/DG-051 登记，不因本阶段短测自动完成。

## 3. 信号路径与初始规则

处理顺序：**PCM16 转 Float32 → 现有压缩器 → 缓慢响度增益 → 现有峰值保护 → PCM16**。

响度控制观察压缩后的、响度增益之前的信号，避免把自身衰减反复计算进去。最终输出另设观察值，用于发现峰值保护额外衰减。原有 −6.0206 dB 补偿保留在压缩器内，不重复叠加固定补偿。

以下是首轮工程参数，听感调试前冻结用于复现；调整必须记录原因并重跑相关用例。它们是产品设计值，不代表标准推荐值或实际听感结论。

| 项目 | 首轮规则 |
| --- | --- |
| 长观察窗口 | 3 秒，使用完整窗口；不足时显示“正在观察” |
| 短观察窗口 | 400 ms，用于瞬态、静音与稳定性判定 |
| 控制更新间隔 | 按音频帧累计 100 ms，结果不依赖调用块长 |
| Balanced 目标 | −24 LUFS，指完整处理链的数字输出目标 |
| 自动增益范围 | −24 至 0 dB；默认不增加原本较轻内容的增益 |
| 目标增益 | `clamp(目标 LUFS − 增益前观察 LUFS, −24, 0)`，仅在有效稳定窗口下更新 |
| 死区 | 1 LU，避免小幅波动反复调节 |
| 变轻速度 | 最大 3 dB/s，样本间连续变化 |
| 恢复速度 | 最大 0.5 dB/s，恢复上限为 0 dB |
| 低电平观察门槛 | 初值 −60 LUFS；无效/静音数据不参与目标增益计算 |
| 峰值保护 | 最后一级始终保留当前 −1 dBFS ceiling，沿用独立 16× 复核 |

仅当持续内容满足稳定性条件时才调整响度；短促敲击和尖峰交给峰值保护。稳定性判据由短窗口持续性决定，并用单次短脉冲用例约束，不能只凭一个 3 秒平均值判断。

目标达不到时显示原因：原本较轻、最大衰减已到、资料不足或峰值保护介入。低于目标的轻声与受限内容不纳入“达到目标误差”的通过统计，须分别报告其实际输出。

- 复用 DG-012 已有的 M/S 计算，明确读数对应的处理位置和时间窗口，先修正旧头文件中与已有参考证据冲突的说明。

- 同一 native 句柄仍由播放线程拥有。界面读取定频发布的副本，不直接并发查询/修改句柄；刷新限为约 4 Hz。

### P4-02：控制器与流边界

| 场景 | 计划行为 |
| --- | --- |
| 第一次启用 | 自动增益从 0 dB 开始；有效窗口形成后缓慢调整，压缩器与峰值保护始终工作。 |
| 同文件静音或短暂停顿 | 冻结目标，保持当前衰减；不根据无效读数追高增益。 |
| 换文件/seek | 清除旧分析窗口，保留当前增益作为过渡起点；新窗口就绪后按速率限制调整，旧内容不参与新内容测量。 |
| 新内容长期不足以分析 | 观察期结束后平滑回到 0 dB 自动增益并显示资料不足，不永久沿用上一文件的衰减。 |
| 暂停/恢复 | 暂停期间不累计音频窗口；恢复延续同一流状态。 |
| 关闭自动响度 | 保留压缩及峰值保护，自动增益平滑回到 0 dB。 |
| 关闭整个处理级 | 先输出既有尾部，后续字节直通；保持现有直通契约，未处理的输出不受 DSP ceiling 约束。 |
| 重置/格式变化 | 丢弃旧格式尾部及测量；按原有句柄生命周期重建，重新观察。 |
| native/数据异常 | 延用逐字节回退并报告错误；无效读数不得变成正增益或 NaN 输出。 |

参数变更在播放线程的块边界接收，音频增益按样本平滑。配置读取、保存和界面操作不能阻塞实时处理。

### P4-03：预设与界面

| 模式 | 调整方向 | 验证重点 |
| --- | --- | --- |
| Natural | 较弱压缩、较慢变化，优先保留内容起伏 | 耳语细节、呼吸、瞬态与高频质感 |
| Balanced | 以现有压缩参数为基线，配合温和响度匹配 | 日常跨内容切换及稳定度 |
| Protection | 更强的持续响声衰减，保留相同峰值保护上限 | 持续过响、突然进入高电平内容及恢复过程 |

模式名称仅描述数字处理方向。三种模式不提高用户的系统媒体音量，不默认允许正自动增益。具体压缩参数和 Protection 目标在 P4-03 的参数表中冻结，再交 P4-04 比较。

升级后默认保持当前压缩参数，自动响度先关闭。用户主动开启后才应用新控制器；模式与开关保存，重启后重新积累观察窗口，不恢复过期测量值。界面以模式、自动响度、当前状态为主，不把完整 DSP 参数表放进主流程。

DG-032 的数字参数差异和保存/恢复可先完成；其听感验收仍须有真实记录。DG-023 本阶段只补响度及模式相关界面，其余未完成项目独立登记。

## 5. 验证矩阵与通过条件

### 自动信号测试

| 用例 | 通过条件 |
| --- | --- |
| 两档持续响度相差 12 LU 的信号切换 | 选取可衰减到目标、未受峰值保护额外限制的信号；观察并收敛后，输出与目标误差 ≤1 LU。首轮按切换后 15–20 秒离线窗口评估。 |
| 安静素材、数字静音、长静音后恢复 | 自动增益始终 ≤0 dB，输出无 NaN/Inf；静音不触发追高，旧窗口不污染新文件。 |
| 单次 ≤100 ms 高电平脉冲 | 自动响度增益偏移 ≤1 dB，峰值由保护级约束；不出现数秒持续追随单次脉冲的衰减。 |
| 增益变化及切换 | 自动增益满足配置的 dB/s 上下行限制与上下限；无块边界增益跳变。原始直通切换单独测试，不能据此承诺全链路无可闻切换声。 |
| 流边界 | 覆盖短于 400 ms/3 s 的文件、尾帧瞬态、EOS、重复 drain、seek、暂停恢复、格式变更、开关和异常回退；正常 EOS 保留全部输入内容。 |
| 采样率/块长/声道 | 沿用 5 采样率 × 6 块长 × mono/stereo；同一流的分块结果在约定的浮点容差内一致，控制更新时间按音频帧对齐。 |
| 峰值 | 处理开启时保留上一阶段 120 个对照用例，加入自动增益/模式切换输出；FFmpeg 16× 参考仍使用原有 +0.05 dB 容差。 |
| 生命周期和配置 | 模式非法值、持久化异常、句柄重建、native 缺失和失败均有明确结果，不扩大权限或影响系统媒体音量逻辑。 |

以上信号时长指离线渲染测试，不等同于设备长时间播放。信号目标可达性、排除原因和失败用例必须在报告中保留，不把静音、未就绪或受保护限制的样本计为达到目标。

### ASMR 与环境音 A/B

ASMR 覆盖耳语、呼吸、敲击、摩擦、高频触发音；环境音覆盖雨声、海浪、风声、白噪声和助眠音乐。每类先有可复现的合成信号，再用已有或有权限的真实素材验证。记录来源/使用权限、SHA256、采样率、声道、关键时间段及参数版本，不把无权分发的录音提交到仓库。

进行两组比较：一组保持同一系统音量，检查实际响度变化；另一组把离线样本匹配到相近响度，比较细节、抽吸、忽大忽小、瞬态和高频质感。只允许为离线听感比较做等响调整，不改变产品正增益上限。

记录输入/输出 M/S/I、增益曲线、峰值、保护介入情况及主观意见。自动曲线通过不代表“自然度通过”；尚未试听的素材标记为待试听。

### 集成、性能及设备

- 保留现有 JVM、原生、纯 C 头与 JNI 合约测试；测试数量按实际结果登记。
- Debug/Release 三 ABI 构建；重跑扩展后的完整性能矩阵，保存时间分布、CPU、RSS/HWM、算法延迟、过程段分配及相对基线差异。音频过程不新增动态分配，窗口查询成本不随播放时长增长。
- 性能目标：相同环境下各配置的 p95 处理时间小于该块音频时长；不满足则登记失败、定位后复测。模拟器数据不替代手机性能。
- 模拟器先做本地播放、自动响度、模式切换、EOS、后台短时恢复和错误提示短测；不等真机才能完成可独立执行的工作。
- iQOO Z9T 真机安排在晚上可用时，做有线/蓝牙/外放中实际可用路由的短测、第三方播放共存及素材听感记录。设备未连接时保留清单，不虚记通过，也不占住其他开发项。
- 30 分钟连续播放、长时间锁屏/后台和最终稳定性测试继续统一留到项目功能全部实现之后。
